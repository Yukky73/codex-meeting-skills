# 導入・接続互換性の修正

公開初版の独立レビューで見つかった3件への対応記録。

| 指摘 | 修正 | 維持する要件 |
| --- | --- | --- |
| Gmail が未対応の MIME 入力を要求 | `link_id`、`attachment_files`、`body` / `html_body` と作成後の `read_email` を使う | 承認済み宛先・本文・PDFだけを作成し、改行と添付を再取得検証する |
| Slack の下書き再取得を必須化 | 作成前の原本照合と作成結果確認を行い、作成後の表示は利用者が確認する | 原文・改行の一致確認と未投稿を維持し、確認待ちを成功と混同しない |
| リンク作成権限が必要 | 標準導入をコピー方式に変更し、リンク方式を任意化 | 6スキルと共通参照を揃え、既存スキル・設定を上書きしない |

Slack初版の「再取得による確認」は現行ツールでは実施不能だった。確認する内容を削らず、方法を利用者の表示確認へ変更した。再取得不能だけで作成失敗とはしないが、利用者が一致を確認するまでは全工程の完了にしない。作成後の確認は追加の書き込み承認ではない。

検証対象はローカル導入・ツール仕様との整合・確認待ちの状態遷移。Windows実機、別担当者の認証、接続サービスへの実書き込みを検証したという意味ではない。
