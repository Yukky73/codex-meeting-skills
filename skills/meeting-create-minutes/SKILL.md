# Meeting Minutes Creator

HubSpot の取引と面談情報を基に、`面談準備/` に未作成の議事録原本を作る。文字起こしから既存原本を更新する作業には使わない。

## 利用者ごとの設定

実行前に [共通設定](../meeting-run-followup/references/configuration.md) を読み、作業ワークスペースの `.meeting-skills.local.md` を確認する。必要な設定が未記入なら、その段階を実行せず不足項目を示す。設定・議事録・承認内容はローカルで扱い、公開リポジトリへ保存しない。相対的なリソースパスは、このスキルの実体ディレクトリを基準に解決する。

## 対象

- 実行者本人の HubSpot owner ID を毎回 `get_user_details` で取得する。名前や固定 ID を推測しない。
- 対象は、owner ID が実行者本人であり、`first_appointment_date` が日本時間で本日の `DEAL` に限る。`first_appointment_date` は初回面談日として扱う。
- 面談開始後に取引の「次回面談」プロパティが空になる場合があるため、対象判定に「次回面談」や `MEETING_EVENT` との関連付けを必須条件として使わない。
- 当日の `MEETING_EVENT` は、取引の補足情報やクアンド参加者の取得に利用してよいが、イベント owner や取引との関連付けで対象取引を除外しない。
- 他担当者の取引、社名を確定できない取引は作成しない。除外理由を報告する。

ユーザーが会社名を指定して「直近の取引に紐づく新規の面談議事録」を求めた場合、直近の `DEAL` は紐付け先の特定にだけ使う。過去の `MEETING_EVENT`、面談日、活動履歴、文字起こしを新規原本の内容や面談日として流用しない。ユーザーが別の日付を指定しない限り、面談日は日本時間の当日とし、指定済みの参加者だけを反映した未記入の `## 議事録` と `## ネクストアクション` を作る。

## 作成と重複判定

1. テンプレート `assets/meeting-minutes-template.md` を読み、その構造を保って使う。
2. `面談準備/` を確認し、同じ `HUBSPOT取引ID` と `面談日` を持つファイルがある場合は作成しない。既存ファイルを変更・上書きしない。
3. 新規ファイル名は `面談準備/{YYMMDD}_{会社名}.md` とする。ファイル名に使えない文字だけ `_` に置き換える。
4. 同じ会社・同じ面談日に複数の対象面談があっても、同一取引の既存ファイルがあれば追加作成しない。別取引で同名パスが衝突する場合は、ファイルを作らず報告する。

## 項目の取得

HubSpot の値は次の優先順位で取得し、根拠のない補完はしない。

- `会社名`：取引に紐づく会社の `name`。会社が 1 件だけなら採用する。
- `面談日`：面談予定日の日本時間の日付を `YYYY/MM/DD` で記載する。時刻は記載しない。
- `部署`、`担当者名`、`mail`：面談に直接紐づくコンタクトを優先する。直接紐づくコンタクトがなければ、取引に紐づく全コンタクトを `、` 区切りで記載する。部署は `department`、氏名は `lastname` と `firstname`、メールアドレスは `email` を使う。
- `クアンド参加者`：取引の owner を記載する。当日の面談イベントから owner または参加者情報を取得できる場合は、それを優先する。取得できなければ空欄にする。
- `流入経路`：取引の「面談チャネル分類」（`mql__`）を使う。
- `HUBSPOT取引ID`：`DEAL` の record ID をそのまま記載する。
- `客先HP URL`：会社名で Web 検索し、公式サイトの URL を記載する。会社ドメインは検索時の照合材料にする。公式サイトを確認できない場合は空欄にする。

`## 面談事前情報` には次のキーを置く。取得できない値は空欄のままにし、推測や「不明」は書かない。

```text
面談日：
業種：
会社名：
部署：
役職：
姓：
名：
面談チャネル：
セミナー/展示会名：
メモ：
```

- `業種` は会社の `industry`、`役職` はコンタクトの `jobtitle` を使う。
- `面談チャネル` は取引の流入元を使う。
- セミナー/展示会名に対応する取引プロパティがある場合だけ記載する。
- `メモ` には取引の `面談事前情報`（`memoisfs`）を要約せず転記する。

## 実行時の注意

- HubSpot のスキル手順に従い、利用可能な object type と read access を確認してから読む。
- HubSpot の読み取りは、`search_crm_objects` と `get_crm_objects` を使う。返却された取引・会社・コンタクトを報告するときは、HubSpot が返した UTM 付き URL を使う。
- HubSpot や Web 検索から取得できない項目は空欄にする。別のレコード、本文、記憶から推測して補完しない。
- 作成後は、ファイルのパス、テンプレート見出し、`HUBSPOT取引ID`、`面談日`、重複がないことを確認する。
- 対象が 0 件の場合はファイルを変更せず、その旨を報告する。
