# Meeting Slack Draft Creator

指定された `面談準備/` の完成済み議事録を根拠に、Slack の `設定済み報告チャンネル` へ新規メッセージの下書きを1件作成する。スレッド返信、既存投稿の更新、他チャンネルへの下書き作成はしない。

## 利用者ごとの設定

実行前に [共通設定](../meeting-run-followup/references/configuration.md) を読み、作業ワークスペースの `.meeting-skills.local.md` を確認する。必要な設定が未記入なら、その段階を実行せず不足項目を示す。設定・議事録・承認内容はローカルで扱い、公開リポジトリへ保存しない。相対的なリソースパスは、このスキルの実体ディレクトリを基準に解決する。

## 対象確認

1. 指定された議事録を読む。会話上で一意に指定できない場合は、候補を示して確認する。
2. `## 面談情報`、`## 議事録`、`## ネクストアクション` に実質的な内容があることを確認する。旧形式では対応する `◆` 見出しを読む。
3. 作成途中、文字起こしのみ、面談先・実施日・議事録内容のいずれかを確認できない場合は下書きを作成しない。議事録にない事実、評価、次アクションは補わない。
4. Slack で表示名ではなくチャンネルIDを確認し、それが `設定済み報告チャンネル` に対応する場合だけ下書きの作成対象にする。Slack が利用不可または未認証の場合は下書きを作成せず、その状況を報告する。

## 下書き本文

議事録の先頭から `## 面談事前情報` または `## 事前情報` の直前までを下書き本文の候補とする。旧形式では `◆面談事前情報` または `◆事前情報` の直前までを候補とする。

- 候補中のメールアドレスは、そのアドレスを含む行ごと削除する。メールアドレスの一部だけを伏せ字にしたり、推測可能な形式へ置換したりしない。
- 会社名、部署名、業務上の担当者名は営業報告に必要な情報として残してよい。電話番号、住所、個人を直接識別する番号、金融情報、健康情報などの機微な個人情報が残る場合は、下書きを作成しない。推測で伏せ字化・要約・言い換えをしない。
- 上記の削除以外では、文字・見出し・箇条書き・順序・空行を変えない。要約、言い換え、追記、見出しの追加、並べ替え、整形をしない。
- 事前情報の見出しと配下の内容は下書きに含めない。事前情報の開始位置を確認できない場合は下書きを作成しない。
- Slack のメッセージ本文へ原文を改行文字を含む単一の本文値として渡し、コードブロック化や引用化によって表示を変えない。改行をスペースへ置換したり、各行を個別送信したりしない。

## 下書き作成と検証

対象チャンネル `設定済み報告チャンネル` と下書きにする本文を確認した後、新規メッセージの下書きを1件作成する。単独実行時は対象チャンネルと本文の明示承認を取得する。親スキルの一括承認が有効なら再確認しない。失敗時は自動再試行せず、下書きIDまたはエラーを確認して報告する。

下書き作成後は、作成結果から下書きIDとチャンネルを確認して、事前情報とメールアドレスを除いた原文が一字一句変更されずに `設定済み報告チャンネル` の下書きとして作成されたことを確認する。作成前の本文と再取得した下書きを行単位で照合し、見出し、箇条書き、空行の位置が一致し、一行に連結されていないことを必須の完了条件にする。

## 報告

- 下書きを作成した場合は、下書きを開くURLと反映元の議事録ファイルパスを示す。
- 下書きを作成しなかった場合は、内容不足、メールアドレス以外の個人情報の検出、議事録の特定不能、チャンネル照合不能、Slack利用不可などの理由を示す。
